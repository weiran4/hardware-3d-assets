# GTNETx2 Core Lesson Implementation Plan

Steps use checkboxes to record implementation and verification.

**Goal:** Add an independently validated, context-bound 5B core wiring lesson without applying v3 rules to x2.

**Architecture:** Independent pure state checker and lesson DOM, integrated into the current chapter routing/gallery. Reuse presentation patterns, not v3 domain rules.

**Tech Stack:** Existing JavaScript ES modules, node:test, Playwright, esbuild and Three.js; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-12-gtnet-x2-design.md`

## Global Constraints

- Begin5B after5A exact-commit release acceptance; preserve the existing publication gates.
- Existing catalog `gtnet-x2`, lesson key `gtnetX2`, anchor `#rtds-chapter-5b`, source revision20250318 PDF249–275.
- White full-width layout, floating PiP without reserved column, no imaginary model or copied source imagery.
- Normal two active protocols; PRP one protocol occupies both modules, separate LANs, setup/runtime GT distinction.
- Full minimum PRP version group and offline reset condition; no v3 RSCAD2.8 shortcut.
- Strict inputs fail closed; direct copper unknown wiring unverified; no numerical latency claims.
- Stop playback on context loss, visibility change, parameter change or reduced motion.
- Core basic/partial coverage only. Preserve regression suites and deployment workflows unchanged.

## Review Focus

- A hidden lesson's manual step must not advance after hardware or generic-mode switch.
- Setup conditions can match without claiming a runtime path or enabling playback.
- Switching stages must not auto-confirm configuration completion; normal protocol fields do not define PRP internal firmware configuration.
- Unknown scalar and null checker inputs fail closed, including mode-irrelevant field corruption.
- Direct optical and copper paths must use truthful topology labels; no switch in a direct path.
